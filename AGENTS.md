# Kal maintenance

This is a PAPER-ONLY research app. Never submit a real order, collect trading credentials, or change the user's $100,000 initial capital / $2,000 combined-trade cap without explicit instruction. Read README.md, data/config.json, current state and recent review history before changing rules. Never erase losses, reset the ledger, fabricate observations or rewrite old fills to match a new strategy.

Use the GitHub source ledger, not browser local state. Collector changes must preserve cash accounting, unowned-sale rejection, fee handling, partial fills and timestamps. New entry/exit rules need a new version and a prospective review decision. Preserve source evidence. Examine at least three relevant primary references for material economic changes.

Reviews: append a dated object to data/reviews.json with title, summary, decisions, evidence and rule version. Run tests and the diagnostics script. Publish through the existing workflow. Validate Actions success and Pages update. Do not confuse simulated execution estimates with actual fills. Do not label sparse, correlated samples as statistical proof. Check event concentration, covariance, data gaps, maker queue uncertainty, worst-tail outcomes, and transaction costs before increasing any exposure within the immutable user cap.

If a full review cannot be completed, record exactly what is missing and do not invent a conclusion. User has authorized evidence-based decisions for subsequent PAPER trading; preserve baseline results and document prospective changes.
